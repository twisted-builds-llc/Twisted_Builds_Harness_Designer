# v0.1.1 plan and progress tracker

Work list for the next draft release. Update the checkboxes and "Status" lines as work lands, so
a new session can pick up where the last stopped. Rules from `CLAUDE.md` still apply (undo
commands, `tr()`, tests with hand-computed values, `docs/file-format.md` kept current).

## Branches and release

- `canvas-pan-preferences` (exists, not on `main`): add touchscreen pinch/pan (step 0).
- `v0.1.1-features`: branched from `canvas-pan-preferences` after step 0, so it holds everything.
- Everything ships as **v0.1.1** (user's choice; the existing v0.1.1 draft/tag was only for testing
  pan preferences). At step 6, ask the user before deleting/re-pointing the old `v0.1.1` tag and
  draft release on GitHub. Release workflow builds AppImage / Windows installer + zip / macOS dmg
  as a **draft**. Merge to `main` only when the user says so.

## Steps (in order; each one small enough for one session)

### 0. Touchscreen pinch zoom and two-finger pan (branch `canvas-pan-preferences`)
- [x] Cause: `CanvasView` never sets `Qt::WA_AcceptTouchEvents` on its viewport and only handles
      `QNativeGestureEvent` (touchpad pinch). Touchscreens send `QTouchEvent`.
- [x] Accept touch on the viewport; two touch points = pinch zoom about their midpoint + pan by
      midpoint movement; one finger keeps behaving like the mouse (select / drag).
      Done in `CanvasView::handleTouch`: a single finger is held back until it moves past the
      drag distance or lifts, so a second finger can still make it a pinch; a drag already
      under way stays a drag. Tap = click, double tap = double-click. Touchpads are left alone.
      No long-press context menu (not asked for).
- [x] Test with `QTest::touchEvent` (synthetic; no touchscreen here - user verifies on laptop).
- Status: done and committed on `canvas-pan-preferences`; all 17 test suites pass. Waiting
  for the user to try it on a touchscreen laptop (needs a new build; see step 6).

### 1. Pin table bulk edit + blind plug column (item 3)
- [x] Multi-cell selection in the connector pin table; typing / Delete applies to every selected
      cell of the column; Ctrl+C / Ctrl+V copy-paste (one value fills all, a block pastes as a block);
      one undo command per bulk edit.
- [x] New `Pin::plugPartNumber` column (cavity/blind plug), counted in BOM and pinout sheet.
      Migration: on open, pins with `isCavityPlug` move their seal part number into the plug column.
- Status: done on `v0.1.1-features`. Schema is now **3** (`migrateV2ToV3`); later v0.1.1 schema
  additions go into the same schema 3 (nothing released uses 3 yet), extending that migration
  if old data needs moving. Pin table: `PinTableView`/`PinCellDelegate` in
  `ui/properties/ConnectorPanel.cpp`, `PinTableModel::setCellTexts` (one undo step). Typing a
  Plug P/N ticks the Plug box; plug pins count their seal too if one is entered. Tests:
  `tst_commands::pinTableBulkEdit`, `tst_tbhfile::schemaV2PlugPartNumbersAreMigrated`.

### 2. Circuit IDs + connect from a pin (item 2)
- [x] Unique circuit ID per wire, auto-assigned on create, editable, duplicates flagged in Problems.
- [x] Circuit ID is a new `Wire` field, separate from `name`; auto-numbered (C001, C002, ...).
- [x] Pin table "Wired to" column: type/pick the far end(s) (`ECU-A : 12`, splice, flying lead,
      commas for several) with autocomplete; moves/adds/removes wires (asks before removing),
      one undo step. Same from a pin's right-click menu (Connect Pin To...).
- [x] Circuit ID in cut list (BOM tab, CSV, PDF) and pinout sheets.
- Status: done on `v0.1.1-features`. `Wire::circuitId`; `nextCircuitId`/`wireEndChoices`/
  `findWireEnd`/`planPinConnections` in `core/model/Queries`; `addWire` numbers new wires,
  `pasteFragment` renumbers only real copies (wires shown on another sheet with their reused
  connectors keep their id and circuit id; tested); schema 3 migration numbers old files' wires in file
  order. App: `checkPinConnections`/`applyPinConnections` in `ui/ConnectorEdits`,
  `commands/UndoBatch.h` (macro opened only when something is pushed),
  `SchematicView::connectPinByName`. Not done: circuit ID drawn on the schematic canvas
  (only Properties, BOM, prints) - ask the user if wanted.

### 3. Connector / terminal / seal / plug library (item 1, plan section 5.7)
Split into parts that each end with tests passing, a commit and a push, so work can stop
between any two. Do them in order.

#### 3a. Library data model (core only, no UI)
- [x] Library entries: connector housing (part number, maker, family, description, cavity
      count + cavity labels, compatible terminal / seal / plug part numbers), terminal (part
      number, gauge range, insulation OD range, gender), seal (insulation OD range), plug.
      Every entry carries `approximate` like wire types (seed data = unverified).
- [x] JSON in the user library and the embedded `library.json` (used entries only);
      `docs/file-format.md`; tests (round trip, merge, used entries).
- [x] Pure compatibility queries with hand-checked tests: parts that fit a housing, whether a
      wire's gauge / insulation OD fits a terminal or seal.
- Status: done. `ConnectorPart` (housing, by part number; `terminals`/`seals`/`plugs` lists of
  compatible part numbers, `cavityLabels`) and one `PinPart` type for terminal/seal/plug
  (`kind` + part number; optional `wireMin`/`wireMax` gauges and insulation OD range) in
  `Harness.h`; `Library::connectorPart`/`pinPart`; merge + `usedLibraryEntries` by part number.
  `calc/PartFit`: `gaugeAreaMm2`, `wireSizeFit`, `insulationFit` (2 % allowance). Gender is
  on the housing only. Tests: `tst_partfit`.

#### 3b. Seed data
- [x] `resources/default-library/` entries for Deutsch DT / DTM / DTP, TE AMPSEAL, Molex CMC,
      every entry marked unverified; shown as "(approx.)" like seed wire types (UI in 3c/3e).
- [x] Test that the seed loads and every entry is marked unverified.
- Status: done. 30 housings, 19 cavity parts; checked against distributor listings, caveats
  in `resources/default-library/README.md` (no Molex CMC housings, no wedgelocks).
  `libraryStore::loadUserLibrary` adds the seed parts once to a v0.1.0 user library and saves

#### 3c. Library dialog: view and edit parts
- [x] Tabs in the existing Library dialog for housings, terminals, seals, plugs: add, edit,

- Status: done. `ui/LibraryPartsPages.*`: Connectors tab (filterable list + form; cavities as a

## Decisions (user answers, 2026-11-16)

- Circuit ID: separate auto-numbered field, editable; wire name stays free text.
- Library: seed data (marked unverified) **and** CSV import. Must stay fully offline: seed data is
  bundled in the app, CSV import reads a local file, users can add their own connectors/parts.
  No runtime network access, ever.
- Blind plugs: migrate seal part number to the new plug column automatically for plug pins.
- Release: everything (pan prefs, touch, items 1-5) is v0.1.1.
